## Goal
Supercharge desktop and Vectra Cloud will independently show the **same curated Managed MCP plugin catalog**. They will not link accounts or synchronize a desktop installation. In Vectra, **Connect** will install a selected reviewed plugin into the **owned Supercharge E2B VM/bot** and attach its MCP server to the chosen conversation after required configuration and permission approval. The mobile app remains a controller of Vectra’s authenticated API; no Plugin API management secret reaches mobile or browser code.

## Implementation
1. **Define and publish one catalog contract.** Add a versioned, read-only catalog in the repository using Plugin API’s existing catalog/manifest schemas. Entries pin immutable HTTPS `.tar.gz` artifacts by SHA-256, include display metadata, permissions, MCP-server choices, required configuration field names and target compatibility. Begin with a real, safe, tested MCP example; add a validation/publishing check so an empty, invalid, mutable, or secret-bearing entry cannot be presented as connectable. The apps fetch the same public catalog feed, not one another’s account or plugin store.
2. **Display the shared list in both apps.** Add a catalog section to Supercharge desktop’s existing Managed MCP UI, separate from its installed inventory and its unrelated CLI-plugin tab. Add catalog browsing to Vectra web and mobile alongside each target bot’s installed inventory. Show version, permissions, source/digest, compatibility, and whether that exact release is installed, awaiting approval, connected, or unsupported. Local-only executable paths must be labelled unsupported on a VM; a pathname on the desktop is never sent as a VM source.
3. **Build target-bound Connect on Vectra.** Extend the owner-checked bot route and typed daemon/controller actions to accept a catalog **entry ID + pinned digest**, not a client-supplied download URL, command, path, token, or VM identity. Re-resolve the catalog and owner, bot, sandbox generation, and conversation on every mutating step; bound payload size and enforce idempotency/revision checks. Permit digest-verified archive installation through the existing Plugin API staging mechanism, retaining per-bot service/store/OS identity and root-held management token. Fix the currently broken `update` action only through the same reviewed source/revision path.
4. **Make Connect an honest review workflow.** In web and mobile, select the VM/bot and an actual conversation (rather than pasting an arbitrary ID); review permissions and execution/network reach; enter required secrets through write-only fields; explicitly trust the exact permissions; install disabled, configure, enable, and apply the bridge to that conversation. Preserve partial state and expose retry/refresh instead of claiming atomic success. Show `installed`, `needs approval`, `waiting`, `applied`, `ready`, and `failed` distinctly. Require a separate opt-in safe real tool call before claiming verified readiness; never auto-execute a newly installed plugin.
5. **Validate boundaries and behavior.** Add catalog-schema/digest/compatibility tests, web route ownership and stale-generation tests, controller archive and negative-authority tests, Flutter/widget tests for catalog/review/connect/error states, and isolated VM tests covering two users/two bots, restart, binding discovery, and removal without altering unrelated MCPs. Verify effective workspace ACL isolation rather than treating per-bot UID/store separation as proof of disjoint filesystem access. Build and test under the existing memory limits. Report production deployment and connected-phone results separately; do not publish or change a live VM merely because local tests pass.

## Scope boundaries
This is the **Managed MCP** catalog, not Supercharge’s separate CLI plugin marketplace. No desktop-to-Vectra account pairing, automatic transfer of a user’s private local plugins, arbitrary REST-to-MCP conversion, or blanket installation into all VMs. Existing installed plugin stores and conversations are preserved; catalog availability never grants trust or execution automatically.
