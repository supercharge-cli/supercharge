# Agent Feature Matrix

This document defines Rust-first acceptance criteria for the daemon’s agent, gateway, execution, persistence, and deployment capabilities. A feature is considered **implemented and tested** only when the repository contains an implementation, deterministic tests, and a documented operational boundary. External-service features are additionally marked as credential-dependent when they require live platform accounts.

| Capability | Rust extension point | Acceptance criteria | Status |
| --- | --- | --- | --- |
| Interactive terminal UI | `supercharge-pager` | Multiline input, history, slash commands, streaming output, interrupt and redirect | Baseline upstream; mixed-case effort parsing/read-policy refinements are present, while dashboard preview, image placeholder recovery, and newer memory modal interactions remain deferred to avoid a broad queue/memory transplant |
| Headless agent runtime | Upstream shell and pager packages | Stable non-TUI entry point with structured events and resumable sessions | Implemented as the optional headless-agent bridge; live model credentials required |
| Tool execution | `supercharge-tools` and workspace crates | File, shell, search, patch, browser, media, and approval-aware tools with bounded output | File-backed MCP argument loading, source-read authorization, immutable snapshots, and configurable whole-read/byte-window policies are implemented and tested; daemon routing and richer policy extension ongoing |
| E2B execution | `supercharge-superagent::e2b` and vendored `third_party/e2b-rs` | Create, run, collect bounded output, enforce limits, and clean up sandboxes | Implemented and unit-tested; live execution requires `e2b` build feature and `E2B_API_KEY` |
| Provider routing | `supercharge-superagent::provider` plus upstream model/config crates | Switch built-in providers and models without code changes; support validated custom OpenAI-compatible endpoints | Built-in profile registry, authenticated `/v1/providers`, secret-free upstream TOML generation, and bounded `/v1/providers/health` diagnostics are implemented; automatic failover, token accounting, and Anthropic runtime coverage remain partial |
| Credential boundary | `supercharge-login` (`GrokComConfig`, `AuthManager`) plus the shell ACP auth handler | Authenticate only the provider the user configured; never adopt an inherited first-party account or an ambient key | Implemented and unit-tested: the provider-first runtime default configures no session authority, `AuthManager` skips the inherited `auth.json` scopes while that holds, and ACP neither advertises nor accepts `cached_token`/`supercharge.ai`/`oidc` without a configured OIDC/OAuth2/external-command authority; explicitly session-configured deployments keep the account flow |
| Persistent memory | `supercharge-superagent::memory` plus shell/pager memory protocol | Restart-safe session-scoped entries, tag/text search, and bounded result count | Daemon memory API is implemented and unit-tested; the CLI memory modal now searches note contents and copies preview text with confirmation. Legacy-to-v2 carryover and typed `/flush`/`/dream` protocol upgrades remain deferred because the upstream batch depends on newer session/task APIs |
| Skills | `supercharge-superagent::integrations` plus upstream skill crates | Discover, trust, invoke, and improve skills using an agentskills.io-compatible layout | Discovery, validated loading, digest reporting, bounded invocation, and optional adjacent `.sha256` trust enforcement are implemented; installation/versioning and improvement loop remain |
| MCP | `supercharge-superagent::integrations` plus upstream MCP crates | Configure stdio/HTTP/SSE servers, authenticate safely, enumerate tools, and isolate failures | Descriptor parsing plus bounded HTTP/SSE and allowlisted stdio initialization, discovery, `tools/call`, structured results, cancellation notices, and local Rust-shell file-backed `use_tool` inputs are implemented; file sources require Read permission, UTF-8/object validation, size/time caps, and immutable snapshots |
| Subagents | shell/session support | Spawn isolated parallel workers, cap depth and budget, collect results, and cancel safely | Bounded subagent execution is implemented with depth, concurrency, timeout, isolated session, and output limits; cancellation and richer provider-native orchestration remain |
| Scheduled automation | `supercharge-superagent::scheduler` and `jobs` | Durable cron/interval jobs, retries, delivery routing, audit trail, and missed-run behavior | Durable interval and validated five-field cron schedules, background due-job claiming, leased job worker execution, bounded result persistence, crash recovery, retries, and target-based result delivery are implemented; richer audit/missed-run policy remains |
| Messaging channels | `supercharge-superagent::gateway` plus gateway modules | Telegram, Discord, Slack, WhatsApp, Signal, Matrix, generic webhooks, email, pairing, rate limits, and cross-channel sessions | Telegram, Discord, Slack, WhatsApp, Signal, Matrix, generic authenticated webhooks, IMAP/SMTP email, and a target-based outbound dispatcher are implemented with deterministic tests; authenticated API rate limiting is implemented; richer inbound cross-channel session federation remains |
| Voice and media | provider registries and gateway clients | Transcription, TTS, image generation, video generation, and platform-native file delivery behind optional providers | Secure `MEDIA:` parsing plus Telegram document, Discord file, Slack upload, and WhatsApp native media delivery are implemented; voice/STT/TTS and generation providers remain |
| Browser/computer use | `supercharge-superagent::browser` plus E2B template | Browser sessions, screenshots, navigation, approvals, sandboxed credentials, and a live user-visible Computer pane | E2B template foundation, Chromium/agent-browser stream supervision, app-compatible status/SSE frames, and authenticated approval-gated navigate/click/fill/type/key/scroll/history controls are implemented; explicit user-takeover UX remains an advanced follow-up |
| Security | config, approvals, hooks, workspace, gateway | Command approval, DM pairing, secrets scoping, sandbox isolation, redaction, and emergency stop | Core approval policy, deny-by-default gateway authorization, pairing, E2B isolation, non-root deployment, bearer-token auth, request limits, security headers, per-session rate limits, persisted global emergency stop/resume, and shared redaction for durable memory/jobs are implemented |
| Observability | diagnostics and daemon status | Structured logs, run traces, health/readiness, usage accounting, gateway state, and crash recovery | Health, capability, connection readiness, daemon status, authenticated `/v1/observability`, durable recovery, aggregate counters, character accounting, execution-duration metrics, tracing-subscriber startup, and per-turn correlation spans are implemented; OpenTelemetry export and provider-token accounting remain |
| 24/7 service operation | headless binary plus Docker/systemd assets | Restart-safe service, durable queue/leases, graceful shutdown, health checks, backups, and upgrade/rollback | Docker Compose, systemd, non-root runtime, health checks, durable jobs/memory/schedules/controls/cursors, background worker recovery, automatic gateway startup, runtime backups, health-checked upgrade/rollback scripts, and manual same-repository GitHub Release automation are implemented |
| Research workflows | batch runner and trajectory crates | Batch trajectories, compression, replay, dataset export, and deterministic test fixtures | Upstream baseline; daemon workflow integration remains |

## Current verified quality gates

The current repository passes the following commands with Rust **1.94.0**:

```bash
cargo +1.94.0 fmt --all -- --check
cargo +1.94.0 clippy -p supercharge-superagent --features e2b -- -D warnings
cargo +1.94.0 test -p supercharge-superagent --features e2b
```

The latest targeted superagent suite reports **49 library tests plus 2 daemon tests passing**; the earlier E2B-enabled quality gate reported **47 library tests plus 2 daemon tests passing**. Email, bounded MCP execution, target-based delivery, cron scheduling, sharing-path validation, and secret redaction each have deterministic coverage.
 Gateway tests are deterministic normalization/authentication tests; they do not claim live platform connectivity without the corresponding credentials and service accounts.

The final release claim distinguishes among **implemented and tested**, **implemented but requiring external service credentials**, **partial foundation**, **planned**, and **not supported**. This avoids presenting a robust daemon foundation as complete feature parity.
